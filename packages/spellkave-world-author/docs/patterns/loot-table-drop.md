# Loot table drop

## Name

`loot-table-drop` — Treasure draw via int roll table + host grant

## Problem

A quest terminal or boss kill should pay a treasure item drawn from SRD
rarity/CR guidance — without smuggling free-text item names into
`roll_table` (int-draw only) and without a kernel "drop on death" arm.

## Forces

- DSL `roll_table()` is **int-only** (`dsl-grammar.md` §RollTable, MF-VAL-317).
- Item identity lives on `entity_definitions` (`srd/magic_item/…`, potions).
- Kill-time and quest rewards already use DM/host computed grants
  ([kill-xp-grant](./kill-xp-grant.md), [quest-xp-grant](./quest-xp-grant.md)).
- Party should perceive that loot appeared (trace / Public entity).

## Solution

1. Author weighted **int** `roll_tables` per rarity/CR/quest/boss band.
2. Keep a TypeScript **code → entity_def_id** catalog beside the generator.
3. At terminal/boss time the host (Aldwin) draws or selects a code, resolves
   the catalog, and **places** the item (or grants quantity) as a computed
   act — same class of solution as kill XP. **Not wired in elven-mini yet:**
   `watchForQuestLoot` (`packages/spellkave-adventure-runtime/src/dm/watches/quest-loot-watch.ts`) is exported but
   never started, and `decideBossLootDrop` (`author/loot-drop.ts:194`) is
   called only from tests, so no loot drops at runtime (bug
   `sk-jay0.3.4.11.6`).
4. Emit a **party-visible trace** (`place_node_traces` / Inscribe) naming the
   drop so players can read it without operator SQL.

## TOML example

Copied from `packages/spellkave-srd-cc/fixtures/base/magic-items/loot-tables.toml`
(generated by `src/chapters/magic-items/loot-tables.ts`):

```toml
# pattern: loot-table-drop
[[roll_tables]]
roll_table_id = "srd/loot/boss/q4-fanatic"
bundle_id = "srd"
result_kind = "int"
display_name = "Q4 Sister Maelis boss drop"

[[roll_table_entries]]
roll_table_entry_id = "srd/loot/boss/q4-fanatic:1"
roll_table_id = "srd/loot/boss/q4-fanatic"
authored_order = 1
weight = 5
result_ref = "20"
```

Host maps `20` → `srd/magic_item/longsword-plus-1` via `LOOT_CODE_CATALOG`.

## Proof

- Offline: `packages/spellkave-srd-cc/src/test/offline/magic-items-coverage.test.ts`
  (loot table fixture + catalog resolution).
- Live (gated, `SPELLKAVE_LOCAL_NODE=1`):
  `packages/spellkave-srd-cc/src/test/live-self-seeding/mechanics/q4-fanatic-loot.test.ts`
  seeds the loot entity directly and reads it back; it does not kill the
  fanatic or draw from the table. No test covers the draw-and-place step
  end to end.

## Known misuse / anti-pattern

- `result_ref = "longsword +1"` on an int table (`MF-VAL-210`, fatal).
- Identity-mapped 1..N weight-1 die smuggled as a loot table (MF-VAL-317).
- Kernel gap for "drop on death" before trying host grant + table draw.

## SRD features that use this

- Magic item treasure by rarity (magic-items.md).
- Elven-mini Q3/Q10 rewards and Q4 boss drop (sk-609b.13) — designed and
  tabled, not yet dropped at runtime (see Solution step 3).
